# Code audit — 2026-10-04

Status: **high-priority findings 1–5 addressed in the uncommitted working tree on 2026-10-04; live verification and findings 7–12 remain open.** This audit originally inspected the `dev` working tree, including uncommitted changes. The original findings below describe that snapshot; see the remediation update before treating them as current behavior. Priority describes potential impact, not observed exploitation.

## Fix first

1. **High — cross-course grade changes.** `backend/src/routes/gradingAssistant.ts:155-194`: `POST /api/grading-assistant/finalize-grade/:tentativeGradeId` checks only `professor` role, then looks up a tentative grade by ID and updates its submission without checking the assignment's course against the professor's authorized courses. A professor with another course's grade ID could finalize it. Require assignment/course authorization in the query and make the grade/finalization writes atomic; test cross-course denial.
2. **High — cross-course tentative-grade disclosure.** `backend/src/routes/gradingAssistant.ts:108-141`: `GET /tentative-grade/:submissionId` checks ownership only when the caller is a student. Any professor can request another course's submission ID and receive its tentative-grade record. Authorize professor access against the submission's assignment/course; test unrelated professors.
3. **High — rubric disclosure.** `backend/src/routes/gradingAssistant.ts:269-286`: `GET /rubric/:assignmentId` requires authentication but no assignment/course access check; a signed-in student outside the course can retrieve rubric criteria. `CLAUDE.md` describes grading rubrics as outside the student course-material corpus. Define the intended student visibility policy, then authorize the endpoint accordingly.
4. **High — sparse XLSX can stall ingestion.** `backend/src/services/documentProcessor.ts:358-375`: extraction trusts each worksheet's `!ref` and synchronously visits every coordinate between its start and end. A sparse worksheet declaring `A1:XFD1048576` yields roughly 17.2 billion cell visits before later ingestion limits apply. Bound visited cells/range or iterate populated cells; test a sparse, very large declared range.
5. **High — cross-session chat state contamination.** `frontend/src/pages/ChatInterface.tsx:46,56-85,87-135`: changing `/chat/A` to `/chat/B` reuses the component; the stream is aborted only on unmount, and async load/stream callbacks do not check the current session. A late A result can show in B (or restore A's draft). Abort on session change and reject stale callbacks/responses; test in-app navigation during a stream.

## Remediation update — 2026-10-04

Findings **1–5** have source fixes and regression coverage in the current uncommitted working tree; they are **not yet validated against a live PostgreSQL instance, production worker, or real browser session**:

- **1–3 (grading):** `backend/src/routes/gradingAssistant.ts` now scopes tentative grades and rubrics to the owning/assigned instructor (student tentative grades only to their owner), uses `req.user.userId`, and finalizes the scoped grade and submission in one transaction. `backend/src/routes/__tests__/gradingAssistant.test.ts` covers cross-course denials, student access, rollback, and grade validation. Rubrics are assumed private to instructors. Unauthorized finalization/rubric IDs return 404; unauthorized tentative grades return 403. Final grades are restricted to integer values from 0 through assignment points, with string feedback. The identity mismatch from finding 6 was also addressed **within this route**; other callers and the resubmission issue still need review.
- **4 (XLSX):** `backend/src/services/documentProcessor.ts` visits populated worksheet cell keys rather than traversing the worksheet's declared rectangle. `backend/src/services/__tests__/documentProcessor.test.ts` tests a sparse, full-range XLSX. This addresses the declared-range loop; it does not impose a new extraction cap on unusually dense documents.
- **5 (chat):** `frontend/src/pages/ChatInterface.tsx` aborts the active stream on route change, clears per-session state, and ignores late load/stream callbacks. `frontend/src/pages/ChatInterface.test.tsx` covers A-to-B navigation during both message loads and streams.

After integrating all three changes, verification passed: backend `npm test` **140 passed, 19 skipped** (opt-in integration suites), backend `npx tsc --noEmit` passed; frontend `npm run lint` passed with no warnings, `npm test` **7 passed**, and `npm run build` passed. `git diff --check` exited 0. These are local tests/build checks, not release acceptance. The original audit's checks below are retained as historical baseline.

## Next

6. **Medium — grading-assistant identity mismatch.** `backend/src/routes/gradingAssistant.ts:27,36,111,122,159,221`; `backend/src/middleware/auth.ts:55-60`: the routes read `req.user.id`, while middleware provides `userId`. Student `GET /tentative-grade/:submissionId` denies the owner, and `POST /generate-tentative-grade` looks up `student_id = NULL` and finds nothing. Use typed `req.user!.userId` everywhere and test these flows. The same mismatch affects `finalized_by` and rubric creation/ownership checks.
7. **Medium — grades survive resubmission of changed work.** `backend/src/routes/student.ts:677-705`; `backend/src/services/agents/GradingAssistantAgent.ts:354-363`: resubmission replaces text/files but retains the previous grade, feedback and grading timestamp; tentative-grade UPSERT does not reset finalization state. Define whether graded resubmissions are allowed; if so, invalidate/review grades transactionally and test the workflow.
8. **Medium — transient storage/DB outage can strand uploads.** `backend/src/services/materials/ingestion.ts:89-105`; `backend/src/services/materials/retryIngestion.ts:13-14`: after 15 minutes, reconciliation moves a pending/reconcile intent to `failed` on errors including transient metadata/download/DB failures, while reconciliation ignores `failed` and retry requires a material version. Distinguish retryable outage from confirmed missing/mismatched objects, or provide explicit recovery.
9. **Medium — professor material download URL outlives short-lived source links.** `backend/src/routes/professor.ts:751-786`: `/materials/:id/download` signs `course_materials.file_path` for 60 minutes without pinning the object generation; the source workflow uses short-lived generation-aware links. Review the intended download policy, then pin the immutable generation and reduce expiry where appropriate. A signed URL remains usable until expiry after authorization changes.
10. **Medium — chat history has no older-page navigation.** `frontend/src/pages/ChatInterface.tsx:74-75`; `backend/src/routes/chat.ts:379-425`: the screen fetches one page (50 messages by default) and has no load-more UI despite `nextCursor`. Add older-message pagination, preserving ordering and current scroll position.
11. **Medium — AI hub lists truncate at page one.** `frontend/src/data/queries.ts:71-85`; `frontend/src/pages/AIAgentHub.tsx:49-51,168-197,223-249,273-290`; `frontend/src/pages/AgentContentViewer.tsx:35-44`: courses, sessions and saved content use single paginated requests without follow-up controls. The saved-content viewer can call a valid deep-linked item “not found” if it is beyond the first page. Add paging and a direct authorized item lookup.
12. **Medium — frontend role state can be stale.** `frontend/src/contexts/AuthContext.tsx:36-55`; `frontend/src/components/ProtectedRoute.tsx:18-27`: localStorage `user` determines UI access without verifying the current account/token. The backend rechecks current role/status (`backend/src/middleware/auth.ts:39-60`), so this is stale/incorrect UI, **not an established backend authorization bypass**. Refresh account identity and handle expired tokens centrally.

Lower-priority follow-ups: `frontend/src/pages/ChatInterface.tsx:138-147,458-462` allows a fresh send while a failed stream has a pending retry; define how a retry should behave after a newer question. `backend/src/routes/gradingAssistant.ts:229-240` uses `courses.instructor_id` for rubric creation although course assignment also uses `course_instructors` (`backend/src/routes/root.ts:589-599,640-650`); check expected owner policy and assignments before changing it. `backend/src/routes/auth.ts` holds a DB client during signup hashing, worth checking under signup load. These are not ranked above the confirmed authorization issues.
